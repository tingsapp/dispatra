# Dispatra web client implementation state

Updated: 2026-09-29. [Specification](spec.md) defines intended behavior.

## Implemented

- Public site `/`, platform administration `/admin`, company dispatcher workspace `/{company}/`, Shipper portal `/{company}/shipper-portal`, Driver portal `/{company}/driver`, and isolated local `/prototype` demonstration.
- The existing dispatcher UI and its layout are retained. Company workspaces load company settings, pricing catalogues and Rate Cards, Shippers, Drivers, Vehicles, Orders, Routes, Monitor and Analytics from the typed `/api/v1` client through TanStack Query. Local demo records and calculations remain confined to `/prototype`.
- Dispatcher forms create and edit directory records; Driver Duty edits save and reload through an API duty session without starting GPS; new Shipper and Driver accounts receive generated passwords shown once. Orders and prospect Quotes use API pricing review and persistence. Dispatcher actions assign/release drivers, create invoices, and explicitly queue Quote and Invoice email. The date filters, Monitor projections, Analytics totals and CSV use API data.
- Google Places selection supplies a formatted Canadian address plus city, province, country, postal code and coordinates for Order stops, Shipper warehouses, Driver addresses and company address. Manual entry remains available; operational address validation is enforced by the API. A Driver's address city defines the service city.
- Shippers can update their own permitted profile fields, create and view their Orders, and read completed delivery proof and invoices. Drivers can manage duty, read assigned routes, report location/arrival/issues, upload evidence, and complete stops and routes through the API. API account and password controls remain in the original portal layouts.
- The live Monitor uses persisted Orders, drivers, route stops, telemetry and attention flags. It does not show simulated driver location or AI recommendations; `/prototype` retains its local simulation.

Public entity references for Orders, Drivers, Shippers and Vehicles now use company-initial codes (for example `DCO-1234`). Vehicle public numbers are separate from fleet Unit numbers; internal UUID relationships remain unchanged. Migration `0012_public_entity_numbers` backfills existing operational records.

## Boundaries

AUTO dispatch and AI, inbound email intake, Stripe payment collection, payroll, push updates, and a native offline Driver queue are not implemented. The map draws straight connections between persisted route stops, not road geometry. Sending an email queues delivery; recipient acceptance is not verified by the browser. Google Places and road routing require configured Google APIs and may incur provider charges. The API does not automatically import records from a browser demo store.
