# Dispatra web client implementation state

Updated: 2026-10-01. [Specification](spec.md) defines intended behavior.

## Implemented

- 2026-10-02: Order details (Orders list and Monitor) offer Complete order for Assigned or In-progress Orders after one confirmation, via `POST /orders/{id}/complete` in company workspaces and a local lifecycle update in `/prototype`. Driver details no longer show Maximum Active Orders or Employment (saved values are preserved). Zone-to-Zone Matrix weight rows keep their entered order; From shows the next lower limit. Verified by `npm run lint` and focused component tests; no browser review.
- Public site `/`, platform administration `/admin`, company dispatcher workspace `/{company}/`, Shipper portal `/{company}/shipper-portal`, Driver portal `/{company}/driver`, and isolated local `/prototype` demonstration.
- The existing dispatcher UI and its layout are retained. Company workspaces load company settings, pricing catalogues and Rate Cards, Shippers, Drivers, Vehicles, Orders, Routes, Monitor and Analytics from the typed `/api/v1` client through TanStack Query. Local demo records and calculations remain confined to `/prototype`.
- Dispatcher forms create and edit directory records; Driver Duty edits save and reload through an API duty session without starting GPS; new Shipper and Driver accounts receive generated passwords shown once. Orders and prospect Quotes use API pricing review and persistence. Dispatcher actions assign/release drivers, create invoices, and explicitly queue Quote and Invoice email. The date filters, Monitor projections, Analytics totals and CSV use API data.
- Google Places selection supplies a formatted Canadian address plus city, province, country, postal code and coordinates for Order stops, Shipper warehouses, Driver addresses and company address. Manual entry remains available; operational address validation is enforced by the API. A Driver's address city defines the service city.
- Shippers can update their own permitted profile fields, create and view their Orders, and read completed delivery proof and invoices. Drivers can manage duty, read assigned routes, report location/arrival/issues, upload evidence, and complete stops and routes through the API. API account and password controls remain in the original portal layouts.
- The live Monitor uses persisted Orders, drivers, route stops, telemetry and attention flags. It does not show simulated driver location or AI recommendations; `/prototype` retains its local simulation.

Imported rate cards (2026-10-02): Add card offers Imported price (Final total only: the external system's total includes tax and Dispatra adds nothing). Imported cards have no Minimum Charge, surcharge checkboxes, Dimensional Weight or Set as default, always sit at the end of the Rate Cards list, are disabled in the New Quote rate-card choice and are not offered on the Shipper form; orders can use them once a TMS integration is connected (not built). The API's existing IMPORTED pricing is unchanged. The local `demo` company has an `Imported price (TMS)` card.

Surcharges and required vehicle (2026-10-02): every Distance, Fixed, Zone and Hourly rate card has `Apply fuel surcharge` and `Apply vehicle surcharge` checkboxes (Imported cards have none). New cards default fuel on for every method and the vehicle surcharge on for Distance and Fixed, off for Zone and Hourly (`defaultVehicleSurcharge`); the local `demo` company's cards were set the same way through the API; they are saved card settings the client engine obeys for every method, matching the API's `apply_fuel` / `apply_vehicle`. Vehicle Types gain a Surcharge ($) field and column. Orders carry a Required vehicle type set at booking: dispatcher New Order and Shipper booking show it and suggest the smallest general type the load fits (`suggestVehicleType`) until someone picks one; choosing a driver no longer changes it. Flatbed presets have an `Open deck` body and refrigerated presets `Refrigeration`. Assignment is meets-or-exceeds in the client (`meetsBodyRequirement`) and in the API (`dispatch.validate_candidate` now checks the required body instead of an exact type match; route planning still checks the load fits the truck). The API change is not yet covered by a test run. New orders start on Same-Day Standard. The dispatcher live estimate lists Vehicle Surcharge and Fuel Surcharge whenever the card applies them, at $0.00 when nothing is charged (`withSurchargeRows`).

Rate card example (2026-10-01): `How pricing works` (formerly `How Pricing Work?`) drops the prose formula, which misdescribed some steps, and shows only the engine-calculated example. The rate-card amount is labelled Delivery charge instead of Freight, and a card with a minimum shows `Charges = …` followed by `Subtotal = $50.00 minimum < $137.77 = $137.77` instead of max(). The Zone to zone example uses one pickup and one delivery zone (`Delivery charge: Pickup → Zone 1 = $20.00`), matching what a zone card prices. Every card's example uses the Same-Day Standard service (or another no-charge service), shown as `Service charge: Same-Day Standard: $0.00`. `loadSimplePricingConfig` now returns copies of the built-in services, vehicle types and accessorials, so editing a loaded config can no longer change the defaults.

Hourly minimum (2026-10-01): Hourly rate cards no longer show or apply Minimum Charge; Minimum Billable time is their only minimum. Saved Hourly cards clear `minimumOrderSubtotal` on load (`/prototype`) and send `minimum_subtotal: 0` when saved through the API; other methods keep their Minimum Charge. Frozen quote contexts keep the minimum they were quoted with, so issued quotes and hourly settlement are unchanged.

Vehicle Types and Settings rename (2026-10-01): the Pricing page is now titled Settings at `/{company}/settings` (old `/pricing` and `/settings/pricing` links still open it) and the account menu item reads Settings. The Profile tab Security & Sessions is now Security. Settings tabs are ordered Rate Cards, Service Level, Accessorials, Fuel Surcharge, Taxes, Vehicle Types, Preferences. Settings gains a Vehicle Types tab (`VehicleTypesSection`) to add, edit and delete types with Name, Max payload, Pallet capacity and Cargo length/width/height; live routes save through the catalogue API (`VEHICLE_TYPE`), and delete deactivates. Vehicle types are vehicle kinds, not sizes: Cargo Van, Refrigerated Van, Cube Van, Box Truck, Refrigerated Truck, Flatbed Truck, Dry Van Trailer, Refrigerated Trailer and Flatbed Trailer, listed alphabetically. Saved `/prototype` presets with earlier tonne or size names migrate on load (surcharge kept), size-only presets are deactivated, and new kinds are added once. The local `demo` company's catalogue was updated to the same kinds through the API; the API seed (`../api/app/operations/seeds/demo_pricing_v1.json`) still has the tonne-based names. ## Boundaries

AUTO dispatch and AI, inbound email intake, Stripe payment collection, payroll, push updates, and a native offline Driver queue are not implemented. The map draws straight connections between persisted route stops, not road geometry. Sending an email queues delivery; recipient acceptance is not verified by the browser. Google Places and road routing require configured Google APIs and may incur provider charges. The API does not automatically import records from a browser demo store.
